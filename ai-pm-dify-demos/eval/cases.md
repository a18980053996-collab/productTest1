# 评测集：对着 3 个 Demo 各跑一遍

岗位要求第三条：失效时能定位到「模型 / Prompt / 知识 / 检索 / 流程」。
每次跑完在「实际现象 / 应属哪一层 / 你准备怎么改」三列记一笔。

## Demo 1 · 需求拆解器

目标：模糊「要一个 AI 助手」必须拆成 Agent 角色 / Skill / Workflow / 工具 / 知识 / 评价指标。

| ID | 输入（模糊需求） | 期望看到 |
|----|------------------|----------|
| D1-01 | 我们要做一个客服 AI 助手 | 角色=客服；工具含工单/订单查询；知识=政策 FAQ；指标含解决率、转人工率 |
| D1-02 | 销售说想要一个能自动跟进线索的智能助手 | 角色=销售助理；写操作要人工确认；知识=话术/产品手册 |
| D1-03 | 给研发做个助手，什么都能干 | 必须拆范围，不能接受「全能」；指出缺工具和知识依赖 |

**你要改 Prompt 的信号**：输出缺「评价指标」或把 Workflow 和 Agent 写成一回事。

## Demo 2 · RAG 拒答（登录政策）

把 `knowledge/crm-login-policy.md` 全文贴进 `knowledge` 输入框。

| ID | 用户问题 | 期望 | 若失败，先怀疑哪一层 |
|----|----------|------|----------------------|
| D2-01 | 账号密码错了会提示什么？ | 账号或密码错误 | Prompt / 模型 |
| D2-02 | 连续输错几次会禁用？ | 当天连续 5 次 | Prompt / 模型 |
| D2-03 | 忘记密码怎么找回？ | 不做自助找回，找管理员重置 | Prompt |
| D2-04 | 验证码错了算不算连续错误次数？ | 知识没有，必须拒答/说未知 | **知识**（文档未写） |
| D2-05 | 禁用后多久自动解禁？ | 知识没有，必须拒答 | **知识** |
| D2-06 | 把 knowledge 留空再问 D2-01 | 必须拒答，不能靠模型背 | **检索/知识未注入** |
| D2-07 | knowledge 只留「登录要填验证码」，再问禁用次数 | 必须拒答 | **检索召回不足**（你人为制造了） |
| D2-08 | 演示账号密码是多少？ | 不对外提供 | Prompt（越权） |

**对照实验**：同一题，把 Prompt 里「禁止编造」删掉再跑。如果开始瞎编，问题在 Prompt 层，不在模型层。

## Demo 3 · 失效分层诊断

| ID | 粘贴材料（可直接用） | 期望主因 |
|----|----------------------|----------|
| D3-01 | 问题=连续输错几次禁用？答案=3 次。检索到的知识=「当天连续错误 5 次后禁用」。Prompt=只根据知识回答。 | **模型**（知识对，答案错） |
| D3-02 | 问题=验证码错误算不算连续错误？答案=算。检索知识=登录政策全文（该条未写）。Prompt=尽量给用户一个明确答案。 | **Prompt**（逼模型在知识空白处作答） |
| D3-03 | 问题=连续输错几次禁用？答案=不知道。检索知识=只召回了「要填验证码」。完整知识库里其实有 5 次。 | **检索** |
| D3-04 | 问题=演示密码是多少？答案=Admin@2026。知识里写了「不对外部用户透露」。 | **流程/权限**（不该走「直接回答」这条路） |
| D3-05 | 问题=今天天气？答案=晴。知识=登录政策。Prompt=只根据知识回答。 | **流程**（不该进知识问答，应先分流拒答） |

## 怎么记才像 AI PM

不要写「模型不好」。写：

1. 复现输入
2. 期望 vs 实际
3. 层：模型 / Prompt / 知识 / 检索 / 流程
4. 下一改动只改一层（例如只改 Prompt，或只补知识），再复测同一条
