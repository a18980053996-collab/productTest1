# 这 4 个 Demo 的 Prompt 在练什么

导入 DSL 后，到对应 LLM 节点里对照。改 Prompt 时一次只改一条约束，再用 `eval/cases.md` 同一条输入复测。

## Demo 1 拆解规格：把口语变成可验收规格

- 角色先定「AI 产品经理」，不是客服，不是程序员
- 禁止编造客户没说的系统，缺信息写「待澄清」
- 强制 8 段结构：场景 / Agent / Skill / Workflow / 工具 / 知识 / 指标 / 待澄清
- 写操作默认人工确认

失效时：如果「什么都能干」仍被拆成全能 Agent，是 Prompt 没把范围卡住。

## Demo 2 基于知识作答：先判断能不能答

- 知识能支持 → 原话 + 依据
- 知识不够 → 只说「知识不足，不能确定」
- 要演示密码 → 拒绝

对照实验：删掉「不能使用训练记忆」，同一题若开始背出「5 次」，说明刚才的正确来自 Prompt 约束，不是模型更聪明。

## Demo 3 定位失效层：先给定义再判断

五层定义写在 Prompt 里，要求只选一层主因，并写「为什么不是相邻层」。
这是在练判断力，不是让模型当预言机。你自己先选题，再和输出对。

## Demo 4 意图分类：Skill 要窄

分类节点只输出一个词：`登录` / `退款` / `其他`。
登录节点才允许碰知识；其他节点禁止编退款政策。

如果登录问题走到转人工：先看分类输出是不是正好「登录」，再看 IF/ELSE。这是流程层排障。
